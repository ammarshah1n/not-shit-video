# 3D without the screensaver

The recovered graph is in `../examples/graph.html`. It is a self-contained Canvas renderer with 3D projection: seeded clustered node field, depth-sorted drawing, camera orbit then accelerating push-through, distance-based labels, near clipping, bounded halos and foreground dust. It is not a Three.js app and needs no GPU framework. Use the simplest renderer that fits the shot.

## Choose the right depth

1. **UI plane + CSS perspective:** most product footage only needs a sharp planar screen, a bevel, restrained shadow, a slow orbit and a defocused background. See Desktop.tsx. Reserve screen reading time before any extreme tilt.
2. **Canvas 3D projection:** graphs, constellations and lightweight particle worlds. Use the included example and edit its fictional HEROES, CLUSTERS and camera path. One coherent colour family.
3. **Three.js / React Three Fiber:** actual models, real lighting, physical materials, shaders, depth of field, complex camera paths. Read `threejs/INDEX.md` and the relevant module. The whole 13-module MIT upstream collection is included, not an empty link catalogue.
4. **Blender:** use when an offline physically based hero shot earns the cost. Pin Blender version, frame range, fps, seed, colour management and asset paths; render headlessly to an image sequence. Check the first/middle/last frames before an expensive batch. No Blender-specific original skill was recovered; this is an optional extension, not a claim that the reference films used it.

## Film-time adaptation

Interactive examples use rAF, a clock or `useFrame`. Film must not depend on elapsed wall time:

```js
const seconds = frame / fps;
mesh.rotation.y = seconds * 0.12;
mixer.setTime(seconds);             // not mixer.update(realDelta)
camera.position.copy(path.getPointAt(progress));
camera.lookAt(target);
renderer.render(scene, camera);
```

For physics, step a seeded simulation with a fixed delta; precompute states from frame zero or bake the result. Rendering frame 900 before frame 100 must not produce a different frame 100. Seed particle positions once. Avoid random calls during rendering.

Remotion's `@remotion/three` integration is optional: install the EXACT SAME version as `remotion`, plus compatible Three.js/R3F packages. Read https://www.remotion.dev/docs/three before use. It is intentionally not a default dependency for a film that only needs planar UI.

## Shot rules

- A camera move needs a destination and an intelligible reveal.
- Macro-to-monument can work; a permanent flight through labels often does not.
- Dock on the product and let the viewer read. Do not make readable UI float away as scenery.
- Foreground, midground and background move differently: parallax carries depth.
- Cap near-lens particle/glow sizes; additive blending must not erase shape.
- Keep labels from colliding, jumping in size or popping at the near plane.
- Lock the colour pipeline and output transfer function. Do not fix incorrect linear/sRGB lighting with arbitrary saturation.
- Render a deterministic sequence; encode constant fps. The graph's live preview hook exists for inspection, not final capture.

Do not turn a beautiful graph into an invented claim about how a private product works. If the graph is a metaphor, label it as a metaphor.
